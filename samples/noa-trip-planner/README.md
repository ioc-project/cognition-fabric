# CF local NOA trip planner

This is a CF-owned copy of the NOA sample application from
[`cisco-eti/oxp-sample-apps`](https://github.com/cisco-eti/oxp-sample-apps/tree/ecfa422a38227bfc0011fb5bf8b796792e481e31/noa-trip-planner).
The application and fictional travel data were copied from that revision.
Upstream was checked through
[`a1edc89`](https://github.com/cisco-eti/oxp-sample-apps/commit/a1edc891e83abd864ab174407249bb702c5d90aa);
the original `noa-trip-planner` application and data have not changed since the copy.
Its Observe SDK dependency is now 1.1.0, following the upstream A2A sample at
that revision. The A2A and SLIM dependency updates apply to the separate
`noa-trip-planner-a2a` application.
Observe SDK 1.1.0 requires protobuf 7.36.2 or newer. The local protobuf constraint
allows version 7; the existing generated CFN bindings use the supported
[older Python gencode with a newer runtime](https://protobuf.dev/support/cross-version-runtime-guarantee/#python-specific-guarantees).
The local CF workflow runs this copy; it does not require an `oxp-sample-apps`
checkout.

The local variant supports `NOA_ENFORCEMENT_MODE=direct` (default) and `proxy`.
Direct mode adds a synchronous CFN `GetDisposition` call before
each LangGraph tool invocation. For every proposed tool call it emits a short
span containing the tool name and arguments, then sends its trace and span IDs
to CFN. `ACTION_ALLOW` executes the tool; `ACTION_BLOCK`, unsupported actions,
or an RPC error skip the tool and return a tool error to the agent. The error
contains the effective `BLOCK` action, a short reason, and an explanation that
the tool returned no data. The explanation is generated by this local adapter;
CFN's response currently contains no reason. Blocking a tool does not end the
MAS workflow. This adapter simulates the enforcement proxy's decision handling;
it does not demonstrate network proxy integration or guarantee that the OXP
span is queryable before the CE decision. Template CE accepts `span_id`, but its
forced verdict does not use that span reference to evaluate the action.

Run it from the CFN service repository after starting the local CF services:

```bash
(cd deploy/local/noa-trip-planner && uv sync --frozen)
task run:full-mas
```

After dependency or lockfile changes, stop NOA and repeat `uv sync --frozen`;
`task run:full-mas` uses the existing environment without synchronizing it.

Set `NOA_MODE=source`, `NOA_ENFORCEMENT_MODE=direct`, and `NOA_MAS_ID` in
the CFN repository `.env`. Use the MAS ID created in the local
CF management UI. The same ID is used as the Observe application ID so the
telemetry and enforcement requests refer to the same MAS. The source runner
sets `NOA_CFN_GRPC_TARGET` to
`127.0.0.1:9003` and uses the shared OTel Collector. Agent and tool names are
used as demonstration identifiers in the request; CFN currently routes by
MAS ID and does not validate those names against management agent records.
The vendored `generated/enforcement.proto` matches the canonical CFN Enforcement
contract. From the CFN repository root, `make proto` synchronizes this copy and
regenerates its Python bindings with protoc 35.1. `make proto-check` verifies both
files without rewriting them. See the [tool setup](../../../README.md#grpc-enforcement-api).

## Proxy mode

Set these in the CFN `.env` before `task infra:up`:

```dotenv
NOA_MODE=source
NOA_ENFORCEMENT_MODE=proxy
```

`infra:up` includes Envoy and its audit support, using the deployment repo's
overlay with CFN-owned configuration. It can run before CFN, NOA, or a MAS exists.
After the CF source services and CE are running and `NOA_MAS_ID` is configured,
`task run:full-mas` loads the MAS-specific routes and supervises both NOA and
its HTTP tool service. Ctrl+C stops both processes.

In this mode, each LangGraph tool call becomes one HTTP POST through Envoy to
an exact `/tools/<agent>/<tool>` route. Envoy calls CFN and forwards only allowed
requests to the tool service. The service invokes the same registered Python
tools and returns their results as LangGraph tool messages. There is no direct
CFN call or local execution fallback in this path, and no automatic POST retry.

The shared registry preserves `schedule_agent`, `itinerary_agent`,
`concierge_agent`, and their existing tool names, so the same identity policy
can be used. The HTTP request carries the proposed-action span's `traceparent`,
captured before that span closes, plus the session ID when available. The tool
service emits a child span in that context. This does not establish the
pre-call event pipeline required for content-sensitive enforcement.

The tool service binds to `NOA_TOOLS_HOST` (default `0.0.0.0`) on
`NOA_TOOLS_PORT` (default 8126), uses only allowlisted agent/tool pairs, and
requires a token inserted by Envoy. Generated configuration is under the CFN
repo's ignored `tmp/enforcement/`. Use `task proxy:logs` for the proxy-side
requests and audit logs. See the [CF local guide](../../README.md#use-envoy-with-source-noa)
for ports, configuration, limitations, and shutdown.
